# Content review sweep, Phases 15 to 19

The final content review sweep for the subject matter expert (the project plan's v1.0 hardening
item). It lists every content file and data snapshot added in Phases 15 to 19, in one table per
phase, with what to verify and which sources could not be read. It was built on 2026-11-13 from
the work packages' notes, `content/`, and `snapshots/manifest.json`. Nothing here has been
reviewed: **every content file is `status: pending` with `review_due: 2027-02-01`** (checked in
all 38 files), and CI fails after that date until each `meta.review` is updated (see
`CONTRIBUTING.md`). Only the subject matter expert may mark content `reviewed`.

**How to read the confidence column.** Content files record a confidence level (`high`,
`medium`, or `low`) beside many items. The counts are the number of times the text
`confidence: high`, `confidence: medium`, or `confidence: low` occurs in the file (this includes
keys that end in `confidence`, such as `domains_confidence`, and inline entries), counted by a script that matches what
`grep -o "confidence: low" <file> | wc -l` returns. Across the 38 files they total 449 high, 230
medium, and 83 low. Some files state confidence only in their prose; the column says so.
**Low** means a project draft, a tool default, or an unverified item: start with those, which are
printed in bold in the "What to verify" column. Snapshots are dated copies of outside sources, not
reviewed content: spot-check them as described. Sources "blocked" were unreachable from the build
network, so nothing in that column was read from the original; the tool's answers say so.

Decisions and risks that need the nurse (law naming, the `ledger_column` exception, personnel
totals, live adapters never run, and sources read only through abstracts) are in `STATUS.md`,
section 2.
